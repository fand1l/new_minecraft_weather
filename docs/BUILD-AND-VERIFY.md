# Як зібрати й перевірити

## Збірка

```bash
./gradlew build          # компіляція + jar у build/libs
./gradlew runClient      # клієнт із модом
./gradlew runServer      # виділений сервер, якщо треба перевірити мережу
./tools/run-model-harness.sh   # 128 перевірок чистої моделі, без гри, за секунди
```

Якщо `runClient` падає **на старті** — це майже завжди міксин, який не знайшов ціль. У лозі
шукати `Mixin apply failed` і назву класу; там же буде видно, який саме інжектор не зачепився.

**Бекенд рендеру — Vulkan.** На OpenGL туман поводиться інакше; перевірено на практиці, що
`set fog thick` не дає видимого ефекту, доки не перемкнутись на Vulkan у налаштуваннях.

## Що має бути в лозі одразу після входу у світ

```
Vibe Weather: managing weather in 1 dimension(s)
```

Чого **не** має бути:

- `failed to take over /weather ...` — злиття команд не спрацювало, ванільна `/weather`
  лишилась глобальною;
- `/weather <щось> is not a subcommand this mod knows` — Mojang перейменувала підкоманду.

## Перевірки в грі

Порядок не випадковий: кожна наступна спирається на попередню.

### 1. Мод узагалі керує погодою

```
/vibeweather query
```

Має вивести всі шість осей, покриття зоною й кількість зон. Якщо «This dimension has no
weather» в оверворлді — сервер не створив менеджер, далі йти нема сенсу.

### 2. Локальність — головне

```
/vibeweather set precip downpour 96
```

Дощ починається навколо вас. Тепер ідіть по прямій ~200 блоків: **дощ має скінчитись**, і на
межі — не рубаним краєм, а завісою, що розріджується. Поверніться назад — знову дощ.

Якщо дощ іде всюди — не працює M2/M4 або сервер шле не ту сітку.

### 2b. Команда має перебивати природну погоду

Після `set` виконайте `/vibeweather query` і **звірте числа**: `set thunder normal` мусить дати
`full (1.00)`, `set wind gale` — щось від 0.65. Якщо в запиті стоїть 0.33 і 0.09, значить
оверрайд знову усереднюється з природними зонами — саме цей баг ловлять перевірки [36] і [37]
в харнесі.

Другий `set` **замінює** попередній у тій самій точці, а не додається до нього. `Zones in this
dimension` не має рости від кожної команди.

### 3. Суха гроза — інваріант 2

```
/vibeweather set thunder normal 96
/vibeweather set precip none 96
```

Небо лишається затягнутим, дощу немає, **блискавки б'ють**. Це те, що ваніль зробити не може
взагалі, і рівно те місце, де я двічі помилявся. Якщо гримить, але не б'є — M10 не застосувався.

Частота — ванільна: приблизно один удар на 10–15 секунд на завантажених чанках. Щоб не чекати
під час перевірки, зменште `gameplay.thunder_strike_interval` (дефолт 100000) до, скажімо, 2000
і зробіть `/vibeweather reload`.

### 4. Лід не зламаний — регресія, яку я вже одного разу вніс

```
/vibeweather set precip none 96
```

У холодному біомі вночі, поруч із водою: **лід має продовжувати намерзати**. Якщо ні —
`tickPrecipitation` скасовується цілком замість половини, і це та сама помилка, яку виправив
останній комміт.

Заразом протилежне: у дощ поставте казан під відкритим небом — з `downpour` він має
наповнюватись помітно швидше, ніж з `drizzle`.

### 5. Нахил опадів

```
/vibeweather set wind gale 96
/vibeweather set wind_direction 90 96
```

Дощ має **нахилитись**, і нахил має змінюватись, коли міняєте `wind_direction` (0 / 90 / 180 /
270). Азимут — це напрямок, **куди** дме вітер: 0 — на південь (+Z), 90 — на схід (+X).

Окремо перевірте **зміну напрямку просто під дощем**: не припиняючи опадів, виконайте
`set wind_direction 270` — нахил має перекинутись протягом двох секунд (інтервал оновлення
сітки). Перед цим переконайтесь через `query`, що сила вітру справді на рівні gale: при
слабкому вітрі нахил є, але настільки малий, що зміну напрямку помітити важко.

Ще одна пастка: `set wind_direction` **не змінює силу вітру**. Якщо перед ним не було
`set wind gale`, азимут запишеться правильно, але нахилятися буде майже нічого.

Якщо нахилу немає: перевірте, чи не стоїть Sodium (буде повідомлення над хотбаром), і чи
`render.tilt_enabled` не вимкнено в конфігу.

### 6. Фізика вітру

При тому ж `gale`:

- пішки на відкритому місці вас **зносить** убік; під дахом — ні;
- у креативі в польоті — **не** зносить;
- у спектаторі — **не** зносить;
- на елітрах: летіть за азимутом 90 — швидше; проти (270) — повільніше; поперек (0) —
  без різниці. Якщо «за вітром» гальмує, а «проти» прискорює, то переплутано знак у
  `WindPhysics.bearingFromYaw` — але харнес це ловить, тож малоймовірно.

### 7. Ванільна команда

```
/weather rain
```

Має відповісти «застосовано в радіусі N блоків навколо вас, а не до всього світу». Якщо
відповіді немає — виконавця не перехопили, дивіться попередження в лозі.

### 8. Туман

```
/vibeweather set fog thick 96
```

Видимість падає. Під водою або в порошковому снігу туман **не має** ставати рідшим — це
окремо захищено в коді.

### 9. Заморозка й перезавантаження

```
/vibeweather freeze on
```

Погода перестає змінюватись, але вітер далі дме й зони далі рухаються — так задумано.

Змініть щось у `config/vibe_weather.json`, далі `/vibeweather reload`. Некоректний конфіг має
бути **відхилений з поясненням**, а стара конфігурація — лишитись робочою.

### 10. Інші виміри

Незер і Енд: `/vibeweather query` має сказати, що погоди тут немає, і нічого не має падати.

## Що дивитись на продуктивності

- `/vibeweather query` показує кількість зон. При одному гравці має стабілізуватись близько
  `zones.target_zones_per_player` (дефолт 3) і не рости.
- F3 → графік TPS на сервері. Тік зон іде раз на 20 тіків, сітка шлеться раз на 40; якщо
  видно періодичні піки саме з таким кроком — це воно.
- Трафік: близько 550 байтів на гравця кожні 2 секунди в усталеному режимі, до ~5 КБ при
  повній ресинхронізації (раз на 30 секунд або після телепорту).
